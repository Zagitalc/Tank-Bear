# Tank Bear working rules

- Android first. Reserve `apps/ios` and `apps/web` for future clients.
- Never commit, push, open a PR, merge, publish, deploy, release, or modify a
  remote repository without the user's explicit instruction for that action.
  Approval of a development stage is not approval to perform those actions.
- Work in small stages. Explain changes, run relevant tests/build/static checks,
  report files and limitations, and stop for review before the next stage.
- Before any authorised commit, present the files changed, purpose, relevant
  verification results, known limitations, and proposed commit message.
- Follow the approved plan in `docs/architecture.md` and `docs/assumptions.md`.
- Actual routed detours are the product's core. Never substitute straight-line
  distance or a road multiplier and label the output a routed saving.
- Preserve source provenance and distinguish price-update age from feed health.
- Do not invent Fuel Finder API fields or terms. Stage 3 requires verified
  official documentation and authorised credentials.
- Keep credentials server-side. Never commit secrets or precise user journeys.
- Do not add accounts, analytics, background location, or unrelated features.
